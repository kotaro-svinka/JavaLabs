# Лабораторная работа №7: Многопоточность в Java

Репозиторий содержит решение лабораторной работы №7, посвященной изучению механизмов параллельных вычислений, синхронизации потоков и современных инструментов асинхронного программирования в Java.

## Содержание работы
1. **Задание 1 (ArraySum):** Многопоточное вычисление суммы элементов массива (разделение задачи на два независимых потока).
2. **Задание 2 (MatrixMaxFinder):** Поиск наибольшего элемента в матрице (потоковая обработка каждой строки с последующим анализом результатов).
3. **Задание 3 (WarehouseTransfer):** Симуляция синхронизированного переноса грузов на склад с ограничением по весу с использованием `CompletableFuture` (Вариант 5).

## Текстовый разбор заданий и логика реализации

### Задание 1: Вычисление суммы элементов массива по половинкам

Программа делит одномерный массив на две равные части и запускает два параллельных потока для подсчета локальных сумм. После завершения их работы главный поток объединяет результаты.

* **Класс-поток:** `SumWorker` наследуется от `java.lang.Thread`. Каждый экземпляр получает ссылку на исходный массив и свои границы индексов (`start`, `end`).
* **Асинхронность:** Потоки запускаются асинхронно через метод `start()`. Главный поток `main` не блокируется и сразу отправляет обе задачи на выполнение процессору.
* **Синхронизация:** Использование метода `join()` организует точку ожидания. Поток `main` приостанавливает работу, пока оба фоновых потока полностью не завершат вычисления, что гарантирует точность итоговой суммы.

### Задание 2: Поиск максимального элемента в матрице

Алгоритм реализует паттерн динамического распределения задач: количество создаваемых потоков автоматически подстраивается под количество строк в матрице.

* **Изоляция данных:** Поток `RowMaxWorker` инкапсулирует работу только с одной строкой матрицы (`int[] row`), что исключает пересечение потоков по памяти.
* **Разделение циклов:** Создание объектов и их запуск разделены на два независимых цикла `for`. Это исключает накладные расходы на выделение памяти во время старта и обеспечивает максимально одновременный запуск всей группы потоков в операционной системе.
* **Редукция:** Главный поток `main` дожидается завершения всех строк через барьер `join()`, после чего выполняет финальный линейный поиск абсолютного максимума среди результатов, возвращенных потоками.

### Задание 3: Асинхронный перенос товаров (CompletableFuture)

Симуляция работы 3 грузчиков, которые переносят товары партиями строго по 150 кг, используя современную модель асинхронного программирования.

* **Инструмент:** Вместо ручного управления низкоуровневыми потоками используется `CompletableFuture.runAsync()`. Задачи автоматически делегируются в системный пул потоков.
* **Использование лямбда-выражений:** Входные задачи передаются в виде анонимных функций через синтаксис стрелочных функций `() -> { ... }`, что заменяет громоздкие конструкции интерфейса `Runnable`.
* **Безопасность памяти (Deep Copy):** Перед отправкой партии на разгрузку создается изолированная копия списка (`new ArrayList<>(currentBatch)`). Это предотвращает состояние гонки (*Race Condition*), когда поток `main` успевает очистить коллекцию до того, как фоновый поток начнет считывать из нее данные.
* **Компоновка задач:** Метод `CompletableFuture.allOf()` связывает все отправленные доставки в одну комплексную задачу, завершение которой главный поток ожидает с помощью блокирующего метода `.get()`.
